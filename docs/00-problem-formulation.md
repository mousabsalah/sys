## 1) الجملة الواحدة (تحتاج تأكيدك نصًا)

- جدول المحاضرات: «اختر توزيع حصص المقررات على (الفترات، الأيام، القاعات، الشعب) بحيث **تقلل** تعارضات الجدول و**القيود الصلبة** = لا طالب/مدرس/قاعة في مكانين في نفس الزمن، و**السعة** كافية، و**توافر** المدرسين والقاعات».
- جدول الامتحانات: نفس الفكرة لكن على **رسم بياني تعارض** (كل مقررين يتشاركان طلابًا هما قوس في الرسم)، والحل = تلوين يعطي أقل عدد فترات دون لونين متجاورين متطابقين.

اكتب الصيغة بصيغتك واعتمدها — كل خلاف لاحق يُحسم عليها.

## 2) المجموعات والمعاملات (مسودة)

| الرمز | المعنى | الوحدة | المصدر |
|---|---|---|---|
| `C` | المقررات (course) | | خطة القسم |
| `S` | الشعب/الفئات الطلابية (section) | | التسجيل |
| `T` | الفترات الزمنية الممكنة | يوم × فترة | التقويم الأكاديمي |
| `R` | القاعات (سعة `cap_r`، نوع `lab?`) | مقعد | إدارة المرافق |
| `P` | المدرسون + توافرهم `avail_{p,t}` | | إدارة القسم |
| `M` | أزواج (مقرر، مدرس) المسموح بها | | الخطة |

معاملات بانتظار بياناتك الحقيقية: أعداد (C, S, T, R, P)، أحجام الشعب، أولوية فترات للطلاب، قيود مباني/مختبرات.

## 3) متغيرات القرار

- `x[c,s,r,t,p] ∈ {0,1}` — المقرر `c` للشعبة `s` في القاعة `r` في الزمن `t` مع المدرس `p`.
- `y[e,t] ∈ {0,1}` — الامتحان `e` في فترة `t` (جدول الامتحانات).
- `viol_*` — متغيرات انتهاك لكل قيد طري (soft) بجزاءات.

## 4) القيود (Hard مقابل Soft)

**صلبة (Hard):**
- لكل شعبة + زمن: `sum_{c,r,p} x ≤ 1` — لا تعارض طالب.
- لكل مدرس + زمن: `sum_{c,s,r} x ≤ 1` — لا تعارض مدرس.
- لكل قاعة + زمن: `sum_{c,s,p} x ≤ 1` — لا تعارض قاعة.
- السعة: `sum x * size_s ≤ cap_r` عند التعيين (كمّي عبر حدود الاقتران).
- التوافر: `x = 0` ما لم `avail_{p,t} = 1`.
- نوع القاعة: مختبرات/معامل فقط للمقررات التي تتطلبها.

**طرية (Soft) — اختر مع الجزاء المناسب لكل واحدة:**
- توزيع متوازن للحصص على الأسبوع (تقليل الأيام الفارغة/المكدسة للشعبة).
- تفضيلات زمنية للمدرسين/الطلاب.
- قرب القاعة من مبنى القسم / إبقاء مواد الشعبة في مبنى واحد.
- تقليل الانتقالات بين المباني في نفس اليوم.

حدد أيها hard وأيها soft بقاعدة: «ماذا يحدث لو انتُهك؟» — إن كان الضرر قابلًا للقياس بكلفة، فهو soft.

## 5) الحجم والتقدير المبدئي

| | محاضرات (مثال 20 مقرر × 8 شعب × 6 قاعات × 20 فترة) |
|---|---|
| عدد x ثنائي | ≈ 20×8×6×20 = 19,200 × عدد المدرسين المسموحين |
| قيود | آلاف الصفوف — تافهة لـ CP-SAT |

قاعدة عامة: CP-SAT يتفوق في بنية (disjunction/تسلسل/لا-تكرار). الرسوم البيانية للتعارض + تعيين فترات = منطقة تلوين الرسم (مهارة `graph-coloring`) ثم تثبيت القيود عليه.

## 6) الترشيح المبدئي للنموذج (decision tree)

- جدول الامتحانات: **CP-SAT / graph coloring** أولًا (بنية تعارض منطقية خالصة، بدون قيم مستمرة).
- جدول المحاضرات: **CP-SAT** أولًا؛ وفي الوصول لحالات ضخمة جدًا (جامعة كاملة): CP-SAT مع time limit + LNS/tabu للتحسين التدريجي (مهارات `large-neighborhood-search` و`tabu-search`).
- لا MILP إلا إن ظهرت أهداف تكلفة مستمرة جوهرية (رواتب ساعات إضافية مثلًا) — عندها تُستخدم مهارة `linearization-techniques` و`integer-programming-techniques`.

## 7) الخطوة التالية الإلزامية (micro-instance)

قبل أي بيانات حقيقية: instance يدوية 2–4 عناصر لكل مجموعة، حُلّت يدويًا، ثم تطابق solver عليها. هذه هي بوابة الجودة.

## أسئلة بانتظار إجاباتك (المالك)

1. المؤسسة: جامعة حكومية/خاصة أم مدرسة؟ وما حجمها (عدد الطلاب، المقررات، الشعب، القاعات)؟
2. هل هناك فصل دراسي واحد دائم أم يتجدد كل ترم؟
3. البيانات المتوفرة اليوم: ملفات (Excel/CSV؟)، قاعدة بيانات موجودة؟ من يجمعها وبأي جودة؟
4. الامتحانات: تزامن المقررات لنفس الشعبة يكاد يكون مستحيلًا — التأكيد على قواعد التزامن المسموحة؟
5. اللغة والاتجاه: واجهة عربية RTL فقط أم ثنائي اللغة؟
6. منصة الاستخدام: ويب داخلي على شبكة الكلية؟ تطبيق مكتبي؟ من يستخدمها (إدارة القسم/الطلاب)؟
7. المخرجات: جداول PDF/Excel؟ إعلان على الموقع؟ تصدير لتقويم؟
8. ماذا نريد أن يفعله النظام في v1 فقط (MVP)؟ — ما خارج النطاق مهم مثله مثل ما داخله.
9. أي قيود خاصة: ساعات المدرسين القصوى/الدنيا، مواد يومية متتابعة، قاعة واحدة لكل قسم؟

بعد الإجابات: نعتمد الجملة الواحدة ← micro-instance يدوية ← اختيار CP-SAT/MIP ← بناء generator + solver ← واجهة العرض.
